# flow-connect

## 工作流

1. 读取交互稿，理清主流程与分支流程。
2. 找到视觉稿中对应的页面和操作控件。
3. 复用或创建 Flow System 组件（见 [components.md](components.md)）。
4. 按布局规则统一页面间距，再放置判断节点。
5. 根据调整后的位置确定起点和终点，选择连线并设置端点。（见 [routing.md](routing.md)）。
6. 按 [routing.md](routing.md) 放置标签。
7. 截图检查并简化多余折点，完成后交付。

页面或判断节点移动后，重新计算相关连线的起点、终点和路径。

输入输出示例见 [examples.md](examples.md)。

## 规则详情


| 主题      | 规则                                                                                    |
| ------- | ------------------------------------------------------------------------------------- |
| 输入      | 交互稿（理解流程）+ 视觉稿（落地连线）；可同 fileKey 不同 node。                                              |
| 锚点      | 有明确操作需连到具体控件；自动跳转等无操作入口的，可连外层 Frame。                                                  |
| 线型      | 正交折线（直角拐弯）；stroke 2；色 `#04BF6A`                                                       |
| 端点      | start=`CIRCLE_FILLED`；end=`ARROW_EQUILATERAL`；用 `vectorNetwork` 顶点分别设置。               |
| 文案      | 与交互稿文案及语言一致。                                                                          |
| 标签与判断节点 | 组件见 [components.md](components.md)；位置与对齐见 [routing.md](routing.md)。                   |
| 字体      | `Noto Sans SC Medium`                                                                 |
| 布局      | 为清晰、完整地展示主流程和分支流程，可调整 Section 尺寸及页面位置；同排页面间距统一为 `200`；有判断节点的两页，间距改为 `200 + 页宽 + 200`。 |
| 写入      | 写入后截图验收，检查连线位置、端点样式、标签居中和判断节点对齐。                                                      |
| 禁止      | 使用 Prototype 连线；臆造交互稿没有的步骤或文案。                                                        |


## 交付前自检

- [ ] 主流程与关键判断分支已画全。
- [ ] 锚点位置符合交互稿操作语义。
- [ ] 每条连线均已尝试更少拐弯的方式；能直连则不拐弯，能使用一次拐弯的连线则不使用多次拐弯的连线。
- [ ] 没有因为固定连接页面边缘中点或固定标签位置而产生多余折点。
- [ ] 三次及以上拐弯的连线，已确认每次绕行都有实际避让需要。
- [ ] 穿过页面的连线显示在页面上方，且箭头仍清晰接到目标页面或控件边缘。
- [ ] 线色 `#04BF6A`，stroke 2，起点 Circle / 终点 Triangle arrow。
- [ ] 标签与判断节点为组件实例，文案、语言同交互稿一致，字体 `Noto Sans SC Medium` 。
- [ ] 标签位置符合 [routing.md](routing.md)，未覆盖页面或判断节点；文字居中对齐菱形。
- [ ] 截图已检查连线位置与对齐。
