# 创建 Section 和需求看板（create-section）

## 执行条件

- 设计资产 `fileKey` 已确认  
- 输出位置为设计资产内的某一页（页名或 page node id）  
- 步骤 1 的需求看板信息已整理完成；Tapd、Wiki 缺失时填写 `/`，其他必要字段不得为空

## 步骤

1. `use_figma` 切到输出位置页（`setCurrentPageAsync`）。
2. **需求看板模板**：
   - 在设计资产所有页面中搜索名为「需求看板」的 Component 或语义相同的需求看板 Instance。
   - 找到 Component → 创建 Instance，填写看板信息；只替换文本内容，不调整模板的结构、样式或布局。
   - 找到需求看板 Instance → 复制该 Instance，填写看板信息；不调整模板的结构、样式或布局。
   - 两者都没有 → 新建 Component，名称固定为 `需求看板`，字段以本文件下方的「需求看板字段」为准，再创建 Instance。
3. 新建 `SECTION`，**名称 = 需求名称**。
4. 将看板 Instance 放入 Section，与 Section 左上角对齐，不额外设置边距。
5. Section 放在不与当前页面已有 Section 或 Frame 重叠的位置；优先放在现有内容右侧，空间不足时放在下方。
6. 填写完成后，按“需求看板检查”逐项检查并修复问题。
7. 检查通过后，返回 Section id、需求看板 id 和检查结果，供后续步骤及交付链接使用。

## 需求看板字段

与步骤 1 的结果一致：

- 标题（需求名称）
- Tapd 链接；没有时填写 `/`
- Wiki 链接；没有时填写 `/`
- 交互稿链接
- 产品经理
- 交互设计师
- UI 设计师
- 设计时间

若文件内已有模板且字段名不同，按语义映射填入即可，不要因字段名称不同而修改模板结构。

## 需求看板检查

填写完成后，读取 Figma 中的实际文本和超链接，并与步骤 1 确认的最终信息对照：

- [ ] Section 名称、看板标题及各字段与步骤 1 的结果一致。
- [ ] 设计时间格式为 `YYYYMMDD`。
- [ ] Tapd、Wiki、交互稿的显示内容正确，超链接指向对应地址。
- [ ] 内容为 `/` 的字段没有超链接。
- [ ] 交互稿链接包含已确认的 `node-id`。

发现问题先修复，检查通过后进入步骤 3。

## 字体与写入

改文本前按 `figma-use` 加载字体；创建节点后 `return` 所有新建/修改的 node id。

## 禁止事项

- 不要把 Section 建到设计资产以外的文件  
- 不要删除或覆盖用户已有的历史需求 Section  
- 不要在未建看板的情况下开始批量复制历史 Frame
