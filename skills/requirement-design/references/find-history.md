# 查找并复制历史稿（find-history）

必须先完成规定范围内的历史稿查找，并输出搜索范围和最终查找结果，才可进入步骤 5。

## 查找范围

仅在**设计资产**内：

1. 遍历**所有页**  
2. 只看含「需求看板」（或能读出「设计时间」的同等介绍模块）的 **Section**  
3. 枚举 Section 内的移动端页面 Frame；参考当前交互稿和设计资产的常用尺寸，不得仅因尺寸不是 `360×800` 而排除。 

不建立持久化索引；每次根据当前设计资产查找历史稿。

## 解析设计时间

从该 Section 的需求看板文本中解析「设计时间」。  
未读取到有效设计时间的 Section，不作为历史稿候选。

设计时间可能有两种写法：

- 「设计时间：20260827」写在同一段文本中；
- 「设计时间：」与日期分别写在需求看板内相邻的两段文本中。

读取规则：

1. 找到含「设计时间」的文本。
2. 文本中已有日期，则直接读取。
3. 文本中没有日期，读取需求看板内相邻文本中的日期。
4. 将日期统一为 `YYYYMMDD` 格式；支持 `YYYYMMDD`、`YYYY.M.D`、`YYYY.MM.DD` 等写法。

本次需求的设计时间来自步骤 1 读取的 TAPD 看板开始时间，开始时间统一转为 `YYYYMMDD` 后参与比较。只有历史稿所在 Section 的设计时间早于本次需求设计时间，才能作为历史稿候选。

## 匹配方式

对页面清单中的每一页，逐一与候选历史稿进行视觉对比，以页面结构和信息层级为主要依据：

1. 页面结构：是否都包含相同类型的导航、内容区、底部操作区、弹窗或抽屉。
2. 模块结构：列表、卡片、表单、详情分组、Tabs 等模块的类型、数量和排列方式是否相近。
3. 信息层级：标题、筛选区、主要内容、操作入口的层级和位置是否相近。
4. 导航标题：可作为辅助确认，不作为单独匹配依据。
5. Frame 名称：仅用于确认，不得仅因名称相近就判定为对应历史稿。

使用 `get_screenshot` 和 `get_metadata` 对比交互稿页面与候选历史稿。

搜索时，不以本次新增的按钮、字段、状态标签等新功能文案作为匹配依据。

## 历史稿处理

对页面清单中的每一页，先从视觉结构最接近的候选中选择历史稿。

多个候选的视觉结构相近时：

1. 选择所在 Section 的设计时间最接近本次需求、且早于本次需求的历史稿；
2. 设计时间相同时，选择创建顺序更靠后的 Frame。

- 找到历史稿：复制到本次 Section，名称改为对应交互稿页面名称；Frame 横向间距为 200，空间不足时换行排布。
- 未找到历史稿：创建名称为交互稿页面名称、尺寸为 `360×800` 的占位 Frame，文案为 `无历史视觉 · 待设计`。

占位 Frame 只用于标记待设计页面，后续按页面设计任务完成设计，不得作为终稿交付。

查找结果需覆盖页面清单中的全部页面。

## 注意事项

不得修改原历史 Frame；只能复制到本次 Section 后再改名和设计。
