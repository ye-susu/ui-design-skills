# 交付清单（delivery-checklist）

仅在步骤 6「完成设计」全部完成后，才能执行交付。

## 交付内容

以下内容汇总自前面各步骤的实际结果，不重新生成历史匹配、页面分类或检查结论。发现记录缺失或结果未通过时，返回对应步骤补充或修复，再继续交付。

1. **本次需求 Section 链接**

  以用户提供的设计资产链接为基础，将 `node-id` 替换为本次 Section id；Section id 中的 `:` 转为 `-`。

  返回前打开该链接，确认能够定位到本次 Section。

2. **历史稿查找与页面设计方式**

   页面清单中的每一页都需记录：

   | 交互稿页面 | 历史稿查找结果 | 来源 node id | 页面类型 | 对比结论 | 最终 Frame 名称 |
   |---|---|---|---|---|---|
   | … | 已复制 / 未找到 | … / 无历史 | 无需调整 / 设计迭代 / 全新设计 | 一致项与差异项 | … |

3. **逐页对照结果**

   页面清单中的每一页都需记录：

   | 交互稿页面 | 交互稿 node id | 终稿 node id | 设计备注 | 模块、信息层级、字段和状态 | 结果 |
   |---|---|---|---|---|---|
   | … | … | … | 已落实 / 无 | 一致 / 差异说明 | 通过 / 未通过 |

4. **Design System 说明**

   按 `design-system-use` 的交付要求，汇总步骤 6 已完成的检查结果与复用、缺失和例外说明。

5. **英文术语对应关系**

   返回按 [translation.md](translation.md) 整理并在步骤 6 核对过的术语对应关系，不重新翻译或另建一份表。

## 交付前检查

全部满足后，才能交付视觉终稿：

- [ ] 步骤 2 的需求看板检查已通过；后续如有修改，已重新检查。
- [ ] 历史稿查找结果和设计任务覆盖页面清单中的全部页面，原历史稿未被修改。
- [ ] 步骤 6 的完成条件全部满足，并有对应的逐页检查结果。
- [ ] Section 名称与需求名称一致，最终 Frame 名称与交互稿页面名称一致。
- [ ] 交付链接可定位到对应的 Section 或页面节点。
- [ ] “交付内容”要求的各项结果已整理完整。

## 无法完成时的处理

仅在以下情况无法继续时，才可以说明本次页面设计未完成：

- 设计资产、交互稿或 Design System 无访问权限；
- Figma 工具持续失败，重试后仍无法完成；
- 缺少会影响设计结果的必要信息；
- 用户明确要求暂停、缩小范围或只完成部分步骤。

发生上述情况时，必须说明：

- 已完成到哪个步骤；
- 已完成和未完成的页面；
- 无法继续的具体原因；
- 恢复执行需要补充的内容。

不得将未完成状态描述为“设计完成”或“视觉终稿已交付”。
