# 获取看板信息（board-info）

用于步骤 1，通过用户提供的 TAPD 看板链接获取并整理本次需求的看板信息。

## 所需信息

- 获取看板信息需要用户提供 TAPD 看板链接。
- 创建 Section 前必须确认设计资产和输出位置。
- 本对话已确认的设计资产可以沿用，但本次输出位置仍需确认。

## 获取方式

1. 使用已登录 TAPD 的浏览器打开看板链接。
2. 读取卡片标题、开始时间及各字段内容。
3. 使用 Figma `whoami` 获取当前登录 ID，作为 UI 设计师。
4. 按下方规则整理需求看板信息。
5. 看板信息整理完成后，确认设计资产和输出位置；缺少时询问用户，信息完整后进入步骤 2。

看板链接无法访问时，提示用户完成登录或授权；未读取到卡片内容前不得根据交互稿、历史稿或其他页面猜测看板信息。
用户明确更正某个字段时，以用户当次提供的信息为准。

## 看板字段

| 字段 | 获取规则 | 缺失时处理 |
|---|---|---|
| 需求名称 | 读取看板卡片标题 | 询问用户 |
| Tapd | 读取卡片中的 Tapd 链接 | 填写 `/` |
| Wiki | 读取卡片中的 Wiki 链接 | 填写 `/` |
| 设计时间 | 读取卡片开始时间，并转为 `YYYYMMDD` | 询问用户 |
| 产品 | 读取产品字段 | 询问用户 |
| 交互设计师 | 读取交互字段中的人员信息 | 询问用户 |
| UI 设计师 | 使用 Figma 当前登录 ID | 无法获取时询问用户 |
| 交互稿 | 读取交互字段中的 Figma 链接，并记录 `fileKey` 与 `node-id` | 询问用户 |

只有已读取卡片并确认 Tapd、Wiki 为空时，才填写 `/`。页面未加载、无访问权限或字段尚未读取到时，不视为字段为空。

设计时间只使用看板卡片的开始时间，不使用执行当天日期、交互稿中的看板日期或历史 Section 的日期。

## 链接字段

Tapd、Wiki 和交互稿属于链接字段：

1. 已获得链接时，填写对应的链接内容，并为文本设置正确的跳转链接。
2. 模板显示 Tapd ID 时，可以显示链接中的 Tapd ID，但跳转地址必须使用完整链接。
3. Tapd 或 Wiki 不存在时，填写普通文本 `/`。
4. `/` 不绑定任何超链接，也不得继承模板原有的链接。
5. 交互稿链接缺失时不得填写 `/`，需询问用户补充。

## 输出结果

```text
boardUrl
requirementName
tapd
wiki
designDate
product
interactionDesigner
uiDesigner
interactionUrl
interactionFileKey
interactionNodeId
```

其中：
- designDate 统一使用 YYYYMMDD；
- tapd 或 wiki 不存在时为 /；
- interactionUrl 必须包含可访问的 Figma URL 和明确的 node-id。
